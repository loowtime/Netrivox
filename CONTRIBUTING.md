# Contributing

1. Explain the problem and security impact in the change description.
2. Keep changes focused and preserve the authorized-target boundary.
3. Add unit or integration tests for new behavior and failure paths.
4. Run formatting, tests, vet, and build locally.
5. Document new CLI flags, output fields, and security implications.

Pull requests should be reviewable, avoid unrelated refactors, and state known limitations or false-positive risks.
